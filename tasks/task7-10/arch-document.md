## Задание 7. Проектирование схем коллекций для шардирования данных

### 7.1 Коллекция Products

```js
{
    _id: ObjectId,
    name: String,
    description: String,
    category: ObjectId,
    price: Number,
    // Остаток товара в каждой геозоне
    stock: [
        {
            geoZone: ObjectId,
            quantity: Number,
        },
    ...
    ],
    // Дополнительные атрибуты
    attributes: {
        color: String[],
        ...
    },
    // Изображения
    images: String[],
    isActive: Boolean,
    createdAt: ISODate,
    updatedAt: ISODate
}
```

#### 7.1.1 Потенциальные кандидаты для шард-ключей

```js
{
    _id: "hashed" // Для равномерного распределения
}
```

#### 7.1.2 Стратегия шардирования

Будем использовать хэшированное шардирование.

#### 7.1.3 Обоснование

Применение хэшированного шардирования позволит равномерно распределить данные и увеличить производительность системы.

### 7.2 Коллекция Orders

```js
{
    _id: ObjectId,
    orderNumber: String,
    customerId: ObjectId,
    orderDate: ISODate,
    status: String,
    geoZone: ObjectId,
    totalAmount: Number,
    // Список заказанных товаров
    items: [
        {
            // Ссылка на актуальный товар
            productId: ObjectId,
            // Кол-во товаров
            quantity: Number,
            // Цена за единицу на момент заказа
            unitPrice: Number,
            // Общая стоимость за позицию (quantity * unit_price)
            totalPrice: Number,
        },
    ],
    // Адрес доставки
    shippingAddress: {
        street: String,
        city: String,
        postalCode: String,
        country: String,
    },
    createdAt: ISODate,
    updatedAt: ISODate,
}
```

#### 7.2.1 Потенциальные кандидаты для шард-ключей

```js
{
    geoZone: 1, // Распределение по локациям
    orderDate: 1, // Распределение по диапазонам значений
    customerId: 1, // Для равномерности внутри зон
}
```
#### 7.2.2 Стратегия шардирования

Будем использовать геошардинг по регионам + диапозонное шардирование по дате заказа.

#### 7.2.3 Обоснование

При использовании такого шард-ключа все заказы пользователя будут на одном шарде в каждой отдельной локации, что позволит быстрее читать данные и равномерно распределять нагрузку.
Для шардирования был выбран такой алгоритм так как он снизит время ответа по разным регионам, уменьшит нагрузки на сервера и поможет содержать все заказы пользователя в одном шарде.

### 7.3 Коллекция Carts

```js
{
    _id: ObjectId,
    userId: ObjectId | null, // Пользователь авторизован
    sessionId: ObjectId, // Для гостей. Используется, если user_id нет.
    status: "active" | "ordered" | "abandoned",
    // Список товаров
    items: [
        {
            productId: ObjectId,
            quantity: Number,
        },
    ],
    createdAt: ISODate,
    updatedAt: ISODate,
    expiresAt: ISODate,
}
```

#### 7.3.1 Потенциальные кандидаты для шард-ключей

```js
{
    sessionId: "hashed",
}
```

#### 7.3.2 Стратегия шардирования

Будем использовать хэшированное шардирование.

#### 7.3.3 Обоснование

Применение хэшированного шардирования позволит равномерно распределить данные и увеличить производительность системы.
